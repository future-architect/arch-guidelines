# 書き上げた後の点検

資料を相手の立場で読み、次の反応が返ってきそうなら、右の手続きまで戻って直す。ある手続きが甘いと、それ以降をいくら直しても良くならない。複数が引っかかったら手前から直す。

| #   | 相手から返ってきそうな反応                           | 戻る手続き                                                                                                                                                                                       |
| :-- | :--------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 「それで、あなたたちはどれがいいと思っているの？」   | 6-4 推奨を添えた問い。推奨が決まっていなければ 4-5                                                                                                                                               |
| 2   | 「他に何があるの」                                   | 3-1 案出し。案は出したが絞った理由が資料に無いなら 4-1                                                                                                                                           |
| 3   | 「その差はうちでは出ないよね」                       | 4 評価。文脈を代入していない一般論の✅⚠️❌                                                                                                                                                       |
| 4   | 「何となくは分かったが、理解できなかった」           | 5 翻訳。技術用語のまま並んでいる                                                                                                                                                                 |
| 5   | 「どういう基準で選べばよいか分からない」             | 6-3 コンセプト名とデメリット。優先の構造を出さずに案を並べている                                                                                                                                 |
| 6   | 「これは私が決めることですか」                       | 6 論点。報告で済むことまで問うている                                                                                                                                                             |
| 7   | 「それは私に聞かれても」                             | 6 論点。設計事項をそのまま聞いている                                                                                                                                                             |
| 8   | 「だから何？」                                       | 7 ストーリー。比較表を順に説明している。3、4 の欠落が出ていることもある                                                                                                                          |
| 9   | 「これはどういう意味？」と細部の質問が続く           | 7-1 背景。なぜ今この話かを見失わせている。技術の詳細より、結論に至った考え方を書く                                                                                                               |
| 10  | 「それで、どのくらい増えるの？」「何が良くなるの？」 | 6-3 費用の示し方。費用の一部しか出ていないか、得る側が示されていない                                                                                                                             |
| 11  | 「後からでもいいのでは？」                           | 7-1 背景と、6 の「先送りしたときの費用」。後から変えると何が起きるかと、作り直しの規模（人数と期間）が、経営層向けの並びでは背景と推奨と比較のページに、担当者向けの並びでは相談事項の最後に無い |
| 12  | 「その数字が違ったらどうなるの？」                   | 6-3。仮に決めた数値に、推奨が切り替わる値が無い                                                                                                                                                  |
| 13  | 「結局こっちに誘導したいだけでは」                   | 7-1 トレードオフ。フロー図の対抗案の箱に、負うものが推奨案の箱と同じ粒度で書かれていない。推奨案が外れたときの損失を書いていない                                                                 |
| 14  | 「結局、打合せで何を決めればいいの？」               | 7-1 推奨案。判断の決め手が1つに絞れていないか、判断のお願いが推奨と比較の結び以外にも散っている                                                                                                  |
| 15  | 「一度には読み切れない」「持ち帰って確認します」     | 7-3 伝え方。1回の打合せの時間と、相手が一度に理解できる量に収まっていない                                                                                                                        |

加えて、次を機械的に確かめる。担当者向けの並びでは、「1ページ目」「当社の理解」「推奨と比較のページ」「背景の今決める理由」を `templates/material.md` の「担当者同士のすり合わせの並び」の読み替えで当てる。

- 背景に、次に何をするために今決めたいのかが書かれているか
- 基準への同意を独立して求めるページで、相手に何を求めるかが1文で書かれているか。報告のページで、相手に何かを求めていないか
- 問いの数は数個に収まっているか。同じ向きに働く論点を1つにまとめたか
- 問いのそれぞれに推奨が添えられているか。提案を添えずに「どれがよいですか」「ご判断ください」「ご指摘ください」と求めていないか
- 相手の価値判断が要る点を、合意の前に結論として書いた文（「進めたいと考えています」「受け入れられると考えています」）が残っていないか
- トレードオフは推奨案に寄せず、フロー図の案の箱で、両側の負うものを同じ粒度で書いたか
- 決め手の行と劣後させた行に、差の大きさが数値で書かれているか
- 推奨案の弱みが比較表の劣る行と一致し（前提が外れたときの損失を除く）、それぞれに緩和策が対で付いているか。推奨案の節で、デメリットと緩和策に同じ番号が振られ、数が揃っているか（緩和策の無いデメリットは「なし（受け入れる）」）。対抗案の節を設けていないか（対抗案が負うものはフロー図の箱）。緩和策に、相手への質問や判断の材料の確認が混ざっていないか。弱みと緩和策が独立したページとして重複していないか。緩和策が、その弱みの影響の数値を実際に小さくするか。どの案にも共通するリスクが弱みや補足に混ざっていないか。緩和策で弱みが消えたと言い切っていないか
- 推奨案が費用を増やす題材では、費用が最初にかかる分・継続する分・規模に比例する分まで、基準の案との比で出ているか。構築費、運用費、効果を金額で書いていないか（金額はクラウドの利用料やライセンス料だけ）。作り直しの規模を人数と期間で示しているか。得る側が工数、件数、期間、リスクの減少で示されているか。1ページ目に金額が無いか。稼働時期と、背景の課題が解ける時期が書かれているか
- 中間成果物で、仮に決めた数値ごとに、外れたときに推奨が変わるか総額だけ変わるかが書かれ、推奨が変わるものには切り替わる値があるか。経営層向けの並びでは、資料の当社の理解が要件を分類と内容の2列でまとめているか。担当者向けの並びでは、要件が独立した節に箇条書きで端的に書かれ（4項目以上なら分類の項目を立てた2階層）、背景の文章に混ざっていないか。背景に、相手が知っている事業の数値や現状、設計や作業の都合が書かれていないか。相談事項が「〜を相談させてください」の1文から始まり（「ご相談します」や、答えごとの帰結を書いていないか）、いつまでに決まるとよいかが、だれの立場かを添えて最後にあるか（「決めたい」「決める必要がある」が残っていないか）。どちらも、相手の事業環境の分析や「相違ないか」の確認を書いていないか
- 背景の「今決める理由」と、本文の「後からでも変えられる」が矛盾していないか。確認をお願いした推奨を左右する前提と、推奨と比較のページの記述（外れても推奨は変わらない、など）が食い違っていないか
- 推奨が切り替わる値の文が、中間成果物の値と一致しているか。切り替わる値が前提の値から大きく離れているとき、後から変えられる決定なら先送りする案を入れた問いに、変えられない決定なら推奨を左右する前提として確認をお願いしたか。していなければ 6-4 に戻る
- 問いの形が、1ページ目の判断の決め手、フロー図の1段目、推奨と比較の結びの問いかけで同じか。節ごとに言い換えて、別の問いに見えていないか
- 結びの問いかけ（ご所感を伺えますか、またはご判断をお願いします）が、推奨と比較の結びの1か所にだけあるか。推奨案のデメリットと緩和策の節が、本文ではなく Appendix の先頭にあるか。1ページ目に、お願いの文が残っていないか
- 緩和する形の問い（この形でよいか）のとき、対抗案に払う費用と、それで減る損失を同じ単位で並べたか
- 弱みに起こりやすさの根拠があるか。効果と費用の差が見積もりの幅より小さいとき、その旨を書いたか
- 同じ指標（時間、費用、社数）が、ページによって違う値になっていないか。対象の区分の定義と前提の件数が同じ定義か
- 判断を左右する用語が、その用語が効く箇所（構成案の説明や比較表の前）で1〜2文で定義されているか。背景に用語の定義や一般的な知識の補足が書かれていないか。一般語に見える技術用語（行、層、系統など）が残っていないか
- 推奨を左右する未確認の前提だけが、1ページ目の確認事項に書かれているか。相手の未決定の事項（価格など）に依る前提を名指ししたか
- 借りた他社方針の出典が中間成果物にあり、資料に他社名が出ていないか。借りた方針は、1ページ目の確認事項か、問いとその決め手（判断の決め手、推奨案の節）の中にだけ出ているか
- 推奨案の結果を別の形（チェックシートへの回答など）に並べ直しただけのページが、本文にも Appendix にも無いか
- 日程を載せる資料では、日程が相手の業種の繁忙期（連休、決算、棚卸し）と重なっていないか
- 資料の各ページが、中間成果物の手続き7 のページ割りと1対1で対応しているか。当社の理解と要件（メッセージの文を本文に書かない）を除く各ページで、メッセージがその1文で言い切られているか
- 資料に手続き番号や作り手側の用語、中間成果物の丸写しが残っていないか
- 比較表の前に、推奨する案とその理由が書かれているか。1ページ目のサマリを除き、同じ推奨を別のページで繰り返していないか
- 1ページ目と、推奨案の節で、案に何を優先する案かが分かるコンセプト名が付いているか。バランス型、ハイブリッド型のような名前をコンセプト名にしていないか
- 案の全体像の図（構成図、時間軸の図、範囲の図のいずれか）が、比較表より前に必ずあるか
- 案の説明、評価、費用が1つの表にまとまり、評価に ✅⚠️❌ と根拠が付き、❌ が事実上対応できないものだけに付いて（負担の大きさは ⚠️ と数値で示して）、観点に大分類（原則 QCD）と小分類の列が付き、比較表の直前に【凡例】の段落と箇条書き（絵文字、グレーの行と略称は表にあるときだけ）があるか。同じ比較を別の表で繰り返していないか。Appendix の表に、本文の比較表と同じ行が残っていないか
- 工数、期間、人数、費用の比に、本文と図（フロー図の箱、デメリットと緩和策の図）で出てくるたびに「（現時点の試算）」が付いているか。比較表はセルに付けず、表の前の文で仮試算と断っているか
- 検討の対象に入らない案を除き、代表パターンで数えて案が4つ以上なら、要件に照らして事実上対応できない案を外し、残った案を比較表に載せたか。足切りを表にせず、構成図の下端の ○× と、図の後の1〜2文で示したか。外す案の図を薄くしたり消したりしていないか。残った案が4つ以上のときに減らしていないか。足切りに使った条件を比較表の行にしていないか。残った案が3つに満たないときは、足切りで外した現行案を比較の基準として加えたか（問いの選択肢には入れない）。足切りの条件に、相談事項そのもの、仮に決めた制約、現行案だけが満たさない要求を使っていないか。足切りの条件が、要件（当社の理解、または背景）に同じ文言で書かれているか。案が3つ以下のとき、または事実上対応できない案が無いときは、足切りせずにすべて比較表に載せたか。検討の対象に入らない案は、一覧と理由を理由ごとに1行にとどめたか。案を4つ以上並べた表と図に、型の分類が見出しの上の行（図では帯）で示されているか。フロー図と、推奨案の節に、下位互換の案、❌ の付いた案、比較の基準の現行案が入っていないか
- 報告のページに、載せる理由が背景とつながって書かれているか（背景と当社の理解のページは除く）
- 問いの前提になる報告の結論が1ページ目に、根拠が推奨と比較のページにあるか。前提にならない報告が後ろか Appendix にあるか。本文の後ろに置くものが「Appendix:」の見出しにそろっているか
- 別の利害関係者の反応が中間成果物に書かれ、資料では関係するページごとに1文までで補足しているか（1ページ目を除く）
- 1ページ目に、提案と判断の決め手が言い切られているか。落とした案の理由や比較の説明が、提案より先に来ていないか
- 背景と報告のページに、推奨と比較のページの数値や理由を重ねて書いていないか。推奨と比較のページの中で、表と文で同じ説明を繰り返していないか
- 問いの選択肢が2つ以上なら、選び分けるフロー図が推奨案の節の前にあり、2段目に向きの違う別の問いを入れていないか
- 担当者向けの並びでは、比較表が本文の1つに統合され、差が出ない行がグレーアウト（Markdown では「（差なし）」。比較表が1列のときは除く）されているか。Appendix に比較表が残っていないか
- 経営層向けの並びでは、本文の比較表が案の仕組み、決め手の行、劣後させた行、費用の行だけで、差が出ない行を Appendix に回したか
- 消しても相手の判断が変わらない文が残っていないか
- 資料の分量が、1回の打合せの時間に収まるか。収まらないなら、中間成果物の伝え方の計画に、何回に分けて各回で何を決めるかが書かれているか
