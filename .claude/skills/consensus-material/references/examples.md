# 一周した例

## DWH 選定

状況: AI 活用に向けたデータ基盤を構築したい相手。並行して、簡易な ELT でファイルを取り込み BI と AI に見せる PoC を進める。年明けから本番構築に入るため、製品を決めないと PoC 環境を作れない。相手の要望は「とにかくデータを一元的に貯めたい」という粒度にとどまっている。

| 手続き | この案件での中身                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | アウトプット                                                                        |
| :----- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------- |
| 1      | 製品が決まらないと PoC 環境を作れず、年明けの本番構築に間に合わない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 決めたいこと: DWH 製品                                                              |
| 2      | 毎日触るのは少人数の分析者、非構造データは当面出てこない、運用に人を張れない。Snowflake に落としたい、と置く                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Snowflake に落としたい。運用の手離れが効く                                          |
| 3      | ロングリスト10件を挙げる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | 10件の案の一覧                                                                      |
| 4      | ロングリスト10件を、要件（国内リージョンで動くこと、権限管理とデータカタログの機能を持つこと）に照らして ❌ の付く7件を中間成果物の足切りの表（型の行に、クラウド事業者の DWH、独立系の DWH、レイクハウスなど）で外し、Snowflake / Databricks / BigQuery の3つを比較表に載せる。文脈を代入すると、BigQuery は全社のクラウド方針に反しないので足切りにはならないが（別クラウドとの接続の負担は ⚠️）、既存クラウドとの距離で Snowflake に劣り、ほかの観点でも上回らないので、比較表に残したまま問いの選択肢には入れない。差が出る観点は、運用の手離れ、非構造データと ML の扱い、既存クラウドとの距離、課金の読みやすさ。SQL 互換と BI 接続はどれでも同じなので、差なしに仕分ける。データ連携性も、接続先が S3 と既存 DWH だけならどれも標準で繋がるので、差なしに仕分ける | 足切りの表（10件。型の行つき）と、3案を7観点で比べ、差が出る4観点を仕分けた表       |
| 5      | 差が出る4観点を、運用の手離れ、AI の計画、クラウド方針、費用の読みやすさという相手の言葉に直す。差なしの3観点も相手の言葉に直しておく                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | 相手の言葉に直した評価軸（差が出るのは4つ）                                         |
| 6      | 評価軸を問いと報告に分け、問いに残った評価軸からコンセプト別の選択肢を作る                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 運用の手離れを優先する Snowflake 案と、AI 活用を先行させる Databricks 案。報告が2つ |
| 7      | 経営層向けの並びで骨子を組む。冒頭で Snowflake 案の推奨と判断の決め手を言い切る → 背景（PoC 環境と年明けの本番構築）→ 当社の理解（国内リージョンで動くこと、権限管理とデータカタログの機能を持つこと、全社のクラウド方針、運用の体制、接続先）→ 推奨と比較（BigQuery を選択肢に入れない理由、型で分けた10件の全体像の図（下端に足切りの条件の ○×）、10件から外した7件と理由（1〜2文）、3案の比較表、選び分けのフロー図、結びで所感の問いかけ）。推奨案の節（メリットと、デメリットと緩和策の図）は Appendix の先頭→ 課金と権限の設計方針                                                                                                                                                                                                                                 | ストーリー                                                                          |

手続き6 で、差が出る4つの評価軸がどこへ行くか。差なしの3つは比較表の行に残すだけで、問いにも報告にもしない。

| 観点                     | 相手の言葉に直すと                               | 行き先                                                                           |
| :----------------------- | :----------------------------------------------- | :------------------------------------------------------------------------------- |
| 運用の手離れ             | 仕組みに詳しくなって10年お守りするのは避けたいか | 運用の手間をどこまで避けたいかで推奨が入れ替わり、相手の価値判断が要るので、問い |
| 非構造データと ML の扱い | 画像やログの AI 活用を、2〜3年内に先行させるか   | AI 活用を先行させるかで推奨が入れ替わり、相手の価値判断が要るので、問い          |
| 既存クラウドとの距離     | 全社のクラウド方針に合わせるか                   | これまでのやり取りで確かめた制約。当社の理解に書く                               |
| 課金の読みやすさ         | 月々の費用が読めるか                             | どの案でも課金と権限の設計で自分たちが吸収できるので、報告                       |

問いに残った2つは同じ向きに働く。画像やログの AI 活用を先行させるなら Databricks、当面 SQL での分析を中心にするなら Snowflake で、運用の手離れも同じ側に倒れる。2つの評価軸は、運用の手離れを優先する Snowflake 案と、AI 活用を先行させる Databricks 案という1組のコンセプトにまとまり、問いは1つで足りる。

場に出す形。

- 問い: 「運用の手離れを優先する Snowflake 案をご提案します。代わりに、画像やログを AI に使う場合は別の仕組みが要ります。AI 活用の先行よりも運用の手離れを取るか、ご判断をお願いします」
- 報告1: ロングリスト10件を3つに絞った基準
- 報告2: 課金と権限の設計方針

報告1 は問いの前提なので、結論だけを冒頭のサマリに置き、根拠は推奨と比較の中で説明する。報告2 は問いの答えに関わらないので、後ろにまとめる。

比較表の行数と、相手に渡る問いの数は比例しない。10候補から3案に絞り、差が出る観点が4つ残っても、場に出る問いは1つである。

## マルチテナントのデータ分離方式

状況: 人事・勤怠 SaaS を約3,000社に提供する事業者。大手企業との商談がセキュリティチェックシート（物理的な分離、自社データだけの復元、専用の暗号鍵）で止まっている。自分たちは開発会社として次期基盤の設計と運用保守を受託しており、年明けから DB の詳細設計に入る。相手はプロダクト責任者。データの分離を強めることは事業部として決まっており、決めたいのはその方式である。中期経営計画が無いため、同業の公開方針から大手企業の獲得を方針と想定した。

資料の節の構成（担当者同士のすり合わせの並び）。

| #   | 節           | 中身                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| :-- | :----------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 背景         | 大手企業との商談でセキュリティ要求に対応できず、保留や失注になる例が出ていること（件数と設問の中身は書かず、背景では要求をひとまとめに言う）。利用企業の数や顧客層のように相手が知っていることと、用語の定義は書かない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 2   | 相談事項     | 物理的な分離を必須とする大手企業の審査に応じるかどうかと、応じる場合の構成案を相談する1文。応じない場合の対応は書かない。最後に、稼働後に足すと作り直しに2名で約3か月（現時点の試算）かかるので、システム構築を担う当社としては12月中に決まることが好ましいこと                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 3   | 要件         | 業務要件（3つの設問（物理的な分離、自社のデータだけの復元、専用の暗号鍵）に回答できる、分離を現行より強化する、機能リリースは夜間のメンテナンス枠（週1回、1時間）で終える）、システム要件（Aurora PostgreSQL で構築する）、その他（詳細設計は年明けから、2028年4月に稼働、運用保守は当社）の2階層の箇条書きで。利用企業と約束したメンテナンス枠は業務要件、日程はその他に入れる。メンテナンス枠は、構成図の下端の足切りの条件になる。分離を現行より強化することは、満たさないのが現行の方式1 だけなので、足切りの条件にしない（方式1 は比較表の他社のデータの遮断の行に ❌）。3つの設問は相談事項（物理的な分離に応じるか）に関わるので、足切りの条件にしない                                                                                                                                                                                       |
| 4   | 構成案と推奨 | 方式5 の提案と理由3つ、案の型と、物理的な分離と論理的な分離の定義（1〜2文）、型の帯を付けた5方式の構成図（下端に「メンテナンス枠（週1回、1時間）で機能リリースを終えられるか」の行を置き、方式3・4 に ×）、図の後の「方式3 と方式4 は、〜メンテナンス枠に収まらず、採用できません。残った方式2 と方式5 を、現行の方式1 と比べます」の文、方式1・2・5 の比較表（方式1 は比較の基準。差が出ない行をグレーアウト）、選び分けのフロー図（審査に応じるか → 稼働時から提供するか）、推奨案の節（方式5 だけ。メリットを1〜2文、3点のデメリットと緩和策を矢印で結んだ図。方式2 の節は設けず、方式2 が負うもの（個別交渉、後から専用 DB を足すと提供まで約3か月（現時点の試算））はフロー図の箱に書く）、結び（以上から方式5 をご提案します、と1か所だけの所感の問いかけ）。推奨案の節は「Appendix: 方式5 のデメリットと緩和策」として Appendix の先頭に置く |

Appendix の比較表は設けない。
